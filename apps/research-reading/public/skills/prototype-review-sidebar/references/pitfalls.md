# 多轮调整后的踩坑记录

| 踩过的坑 | 可复用的处理方式 | 核验方法 |
| --- | --- | --- |
| 科研、阅读分别补 CSS，宽度、按钮位置和底栏逐渐不一致 | 共用 420px/40px 布局与统一样式，变更后两槽位同时看 | 同宽度比较三模式，窄屏检查底部按钮 |
| 卡片点击会框选，但用户完全不知道 | 标题旁明确放“定位”“框选校正”，详情同样提供 | 不看说明也能找到两个入口 |
| 一级标题内部混入另一套 2.1、2.2 编号 | 展示编号从树结构生成，ID 独立不改 | 插入、重排、重命名后关联仍对 |
| 把“删来源小字”理解成“删需规摘录” | 原文、来源元信息、AI判断分别对待 | 需规摘录完整，来源小字和 AI 初审不回归 |
| 合规与 PRD 强行同步名称 | 分别保存，关系通过 ID 建立 | 一个模式改名，另一个不自动改名 |
| 将一个产品的 PDF 语言设置复制到另一个产品 | 只复用侧栏；业务规则独立配置 | 宿主业务设置无跨产品污染 |
| “暂缓处理”只加到下拉框，导入/筛选/恢复不认识 | 枚举、校验、统计、存储与展示一起改 | 两产品全部12种切换、刷新、导入、恢复 |
| 已完结只能从待审核进入，违背自由切换 | UI、前端和服务端同时移除门禁 | AI 待做直接已完结，暂缓直接已完结 |
| 换状态导致当前内容、绑定或框选变化 | 状态是局部补丁；时间只记录实际完结 | 状态前后比较其余字段 |
| 多对多关联自动扩散成不相关功能，取消后又回来 | 区分直接关系、派生关系、显式排除；只补一层 | 多来源关联取消后保存、刷新、导入 |
| 旧文档范围套到新文档，框选看起来有效但指错 | 保存产品、文档与页签上下文；恢复前验证对象 | 相同 DOM 但不同文档必须阻止错位 |
| 框选被侧栏、滚动容器或浮层裁切，标记重叠 | 计算实际可见区域，监听滚动/resize，标记避让 | 右下角密集注释、滚动、缩放、折叠侧栏 |
| 定位通过点击操作按钮触发真实业务提交 | 白名单只展开视图；宿主负责安全准备 | 定位前后业务数据不发生写入 |
| 清空校正区域后旧框仍显示 | 明确空范围是移除覆盖，关闭绘制与旧覆盖层 | 保存空范围后不残留旧框 |
| 多窗口保存互相覆盖，轮询覆盖草稿 | expectedRevision 与冲突反馈；表单草稿独立 | 两窗口同一版本提交，后者冲突且输入保留 |
| 只改内置 PRD，用户看到的持久版本仍旧 | 明确种子与活动记录两套来源，提供备份后更新 | 旧访客保留修改，新访客读取新基线 |
| 新模式依赖本地 `/api`，推到 GitHub Pages 全部404 | 显式 browser/service 模式，静态模式不请求 API | 从真实子路径打开，不只跑开发服务器 |
| 粗暴清 localStorage 或 IndexedDB 让新版本生效 | 项目namespace隔离，只重置明确选择的评审key | 宿主业务数据与另一产品哈希不变 |
| 相对资源路径写成 `/assets/...` | 使用构建基址，静态部署前走真实子路径 | 子目录下刷新、导出、资源加载正常 |
|复制源码漏了 Context、声明或最后一层 CSS | 按导入闭包打包，独立目录构建验收 | 原项目目录不可用时仍可运行 |
| 通用目录已替换，校验仍只接受旧 READ-/F 编号 | 稳定 ID 与业务编号脱钩，保留形状及重复校验 | 新种子、通用选择器能保存，损坏数据仍拒绝 |
| 组件编译通过，基础按钮样式、关闭图标和弹窗偏移仍依赖原 App | 一并提取必要 reset，限定样式作用域，移除业务布局依赖 | 实际打开弹窗并检查窄屏，不以构建成功代替视觉验收 |
| 从功能新增注释却没有初始框选，因为上下文只写了 page | Shell.context 与目标导航使用一致的上下文字段 | 从功能详情新增注释，应能看到已保存框选区域 |

## 本版明确边界

1. 这是从实际源码提取的双槽位 React 模板，不是任意框架、任意模块数量的组件平台。
2. PRD／注释有完整修订号保护；合规内容有保存前快照检查，合规手动框选仍为浏览器记录，没有服务器修订历史。多人同时校正同一点需要进一步服务化，不能承诺实时协作。
3. 原始 `elementSelector` 在没有稳定 ID 时会回退到结构位置选择器。直接复制可以画框，但用于真实长期评审应主动给目标加稳定 ID，避免列表重排造成漂移。
4. 备份文件是 JSON，可供保留、诊断和恢复使用。注释可从界面导入；完整评审备份当前没有“一键恢复全部”的入口，不要告诉用户已具备该功能。
5. 改 namespace 相当于进入另一份存储，不是迁移。已有用户需要显式数据迁移流程；不能用改前缀隐藏旧数据来声称升级成功。
6. 历史版本可保留旧需求，不应为纠正文案回写过去；当前版规则与原型必须一致。不要根据旧 skill 的“保留故事线”要求把已删除模式加回来。
